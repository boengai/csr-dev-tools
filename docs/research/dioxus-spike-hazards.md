# What could make the Dioxus spike measure the wrong thing?

Researched 2026-11-25 against Dioxus **v0.7.10**, spot-checked against **v0.8.0-alpha.3**, for [Do tool pages prerender their body or only their head?](https://github.com/boengai/csr-dev-tools/issues/26). Four readers each answered one topic from source and issues; a separate sceptic then tried to refute every claim. **No Dioxus build was run.** The React-side tag checks ran headless Chromium over an existing `dist/`.

"read" means seen in source or docs, "reported" means an issue or PR says so, "inferred" means reasoned from those.

## Hazards

### They corrupt the numbers without an error

- **Debug symbols are on by default.** `--debug-symbols` defaults to true, so `wasm-opt` runs with `--debuginfo`, and splitting forces `debug=true` and skips stripping. [PR 5912](https://github.com/DioxusLabs/dioxus/pull/5912) reports 25.4 MB against 529 KB for a split versus unsplit counter. Pass `--debug-symbols false` and check for DWARF. ([target.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/cli/src/cli/target.rs#L100-L105), read)
- **A `wasm-opt` failure still exits 0** and ships unoptimised wasm. ([wasm_opt.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/cli/src/wasm_opt.rs), read; [5705](https://github.com/DioxusLabs/dioxus/issues/5705) open)
- **`wasm-opt` can abort on ordinary, unsplit release builds** on 0.7.10. The fix is in alpha.3 only. Reported workaround: `--debug-symbols=false`. ([5119](https://github.com/DioxusLabs/dioxus/issues/5119), [PR 5736](https://github.com/DioxusLabs/dioxus/pull/5736), reported)
- **A split module can silently be an empty trampoline**, with its code left in the core chunk. The size table then looks valid and is wrong. ([PR 6113](https://github.com/DioxusLabs/dioxus/pull/6113), reported)
- **The `wasm/` workspace profile is inherited.** `wasm/Cargo.toml` sets `codegen-units = 1`, the [4769](https://github.com/DioxusLabs/dioxus/issues/4769) trigger, and `dx` inherits release unless a `[profile.web-release]` exists, with no warning. ([request.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/cli/src/build/request.rs#L3046-L3072), read)
- **Splitter defects reproduce on stable Rust**, not only nightly: [5769](https://github.com/DioxusLabs/dioxus/issues/5769) and [PR 5772](https://github.com/DioxusLabs/dioxus/pull/5772) report `format!()` dropping output and a trap on every page load. (reported; the write-ups state they are AI-authored)
- **One `/tools/:key` route is one split point for all tools.** Per-tool chunks need one variant per tool, `#[component(lazy)]` or `lazy_loader`. ([route.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/router-macro/src/route.rs#L293-L327), inferred from source)
- **Two tools understate 84.** The unsplit module grows with every tool, and the splitter's shared-chunk pass is a no-op. (inferred)

### They break or distort the page

- **The root id defaults to `main`, not `root`.** Our CSS targets `#root`. If the id is missing, Dioxus renders into a detached element. Use `Config::rootname("root")`; the doc example's `root_name` does not exist. ([cfg.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/web/src/cfg.rs#L51-L104), [dom.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/web/src/dom.rs#L57-L81), read)
- **The first render appends and never clears the root**, unlike React. ([core.ts](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/interpreter/src/ts/core.ts#L36-L49), read)
- **A literal `<title>` in the template gets the app title appended**, and the home page would ship it. Use the `{app_title}` placeholder. ([web.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/cli/src/build/web.rs#L557-L568), [5979](https://github.com/DioxusLabs/dioxus/issues/5979))
- **`dx` adds no stylesheet link by default.** Without `with_static_head(true)` the blank interval is unstyled, since the page background is in that CSS. ([css.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/manganis/manganis-core/src/css.rs#L38-L45), read)
- **A split route with no `SuspenseBoundary` above the `Outlet` blanks the whole app.** ([router README](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/router/README.md#L123), read)
- **A chunk that fails to load never settles**, and chunk names change on every build. Unknown URLs answer 200 with HTML, so a tab left open across a deploy could stay blank. ([PR 6042](https://github.com/DioxusLabs/dioxus/pull/6042) and [6090](https://github.com/DioxusLabs/dioxus/issues/6090) reported; the combination is inferred)
- **Enabling the `wasm-split` feature without the flag breaks the app.** ([5062](https://github.com/DioxusLabs/dioxus/issues/5062))
- **`public/index.html` and `public/wasm/` collide with build output.** The first overwrites the generated page; the second is deleted. (inferred from source)
- **`dx` runs its own Tailwind 4.1.5** if `tailwind.css` is in the crate directory, and ignores its errors. ([tailwind.rs](https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/cli/src/tailwind.rs#L15-L48), read)
- **Do not copy `index.html` to `404.html`**, as the Dioxus publishing guide says for GitHub Pages. On Cloudflare Pages that turns off the fallback the port must reproduce. (inferred)
- **Restamp after every build.** Any wasm change renames the JS file too, and old files persist in the output directory. (read)

### They limit what the measurements can say

- **Local hosts differ from production.** Playwright runs `pnpm dev` and Lighthouse runs `vite preview`; `public/_headers`, the 308 redirect and the 200 fallback apply only on Cloudflare Pages. (read)
- **No e2e spec asserts a head tag.** (read)
- **A removed element stays the LCP element** unless a larger one renders, so a placeholder can improve LCP without the tool being usable sooner. ([web.dev](https://web.dev/articles/lcp), read by one agent, not double-checked)

## Do not carry forward

The sceptics refuted or narrowed these claims: the Playwright spec only locates an existing meta tag; web-sys `Element` comes through `mounted`; 5769 is nightly-only; a per-tool `key` remounts the page; the rule for a suspended `Title`. The corrections are below.

## Appendix: every claim and its verdict

### Mounting and static placeholders

Without hydration, 0.7.10 APPENDS: the first render calls appendChild on the root, and I found no code that clears existing children. A static placeholder inside the root therefore stays, above the app, until something removes it. Dioxus never does. App code can (web-sys; document::eval also works but needs 'unsafe-eval', which the CSP allows), or CSS can hide it. Neither needs an inline script. The root defaults to id "main"; Config::rootname, rootelement or rootnode change it. dx uses a crate-root index.html as the template, so static body markup is kept and one external module script is injected. Release output contains no dx loading screen; that page exists only in dx's dev server. Nothing was run in a browser.

Found by the sceptic:

- CSS-only hiding is reversible (inferred from read source). If the root boundary suspends again after mount, e.g. client navigation to a split route that is not yet loaded with no app SuspenseBoundary above the Outlet, the (None, true) arm replaces the live children with the fallback comment: https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/core/src/suspense/component.rs#L507-L544 and https://github.com/DioxusLabs/dioxus/blob/v0.7.10/packages/core/src/diff/node.rs#L234-L256. The root then holds no app element, so the :only-child and :empty rules would show the placeholder again. On a stamped page that would be the landing tool's heading and description. The [data-dioxus-id] rule does not reverse, and a removed node cannot come back.
- Contrast with today (read): React's createRoot().render clears all existing HTML in the root on first render (https://react.dev/reference/react-dom/client/createRoot, Caveats; used at src/main.tsx:8). Dioxus's append is therefore a behaviour difference, although today's root is empty (index.html:98).
- Existing root styling (read): src/index.css:134-149 targets #root with `flex h-dvh w-full flex-col overflow-hidden` plus the page background and gradients. ### The head-stamping build step

At 0.7.10 a release web build writes target/dx/APP/release/web/public/: index.html, assets/APP-dxhHASH.js, assets/APP_bg-dxhHASH.wasm, plus public/ files. A crate-root index.html is the template, edited only by string replacement, so our head tags, ld+json and font links pass through. dx injects a JS preload and a module script. It also appends the configured or default title to a literal title tag (#5979); today's check would not notice. Asset URLs are root-absolute (/./assets/...), so copies at any depth resolve. Today's check is "at least one match, first replaced", not exactly one. dx writes no 404.html, so Pages' unknown-URL fallback is unchanged. Stale files persist between builds. Routes can come from a host-compiled Rust binary or Node reading shared data.
